Arborun MCP｜验收视角的执行树
├─ 用户要求（2026-11-05）
│  ├─ 人验收时看测试与前端效果，不看代码；中间过程按人的关注程度分层。
│  ├─ 拍板的决定在提问阶段确认，不进入树。
│  ├─ 采用树：只有一个输出的环节退化为路径，最终验收在主干末端。
│  ├─ 视觉：参考 Claude 的克制风格，暖中性底色、单一陶土色强调、细线与柔和阴影；标题衬线、正文无衬线；浅色与深色跟随宿主主题（data-theme）或系统设置。
│  └─ 无限画布、双击进入任意节点、悬停反馈、可拖动卡片。
├─ 数据与引擎
│  ├─ 新节点类型：result（要达到的效果）与 test（当……时，应该看到……）。
│  ├─ test.by 记录设定者：user 为验收标准，agent 为补充检查。
│  ├─ result 与 group 同为容器：不可领取，状态由内部测试与步骤汇总。
│  ├─ 每个 result 至少需要一个 test；只有 test 可以标注 by。
│  ├─ arborun_plan 更新时，用户设定的测试不得修改或删除；用户可在树中编辑。
│  └─ 验收树文字输出标注“用户设定／Agent 补充”与“要达到的效果”。
├─ 界面
│  ├─ 主干：根的子节点依次排列，末端为虚拟的“用户验收”节点。
│  ├─ 子节点依赖前一个时连成路径，否则为分支；效果内的测试并排、无顺序。
│  ├─ 效果下的实现步骤收进虚拟“Agent 工作”节点，线条最淡。
│  ├─ 进度按测试计数；修复中的 Agent 工作不显示为用户问题。
│  ├─ 默认全部折叠：只显示主干；展开或进入节点后才显示其内容。
│  ├─ 节点为圆形，分三段：上为名称，中为具体内容（运行中改为 Agent 正在做的事），下为状态图标。
│  │  └─ 状态图标：完成为勾、等待为钟面、运行中为该 Agent 颜色的播放符号；未通过为叉、需处理为叹号。文字仅作读屏与悬停提示。
│  ├─ Agent 进度：圆外一圈粗描边，每个 Agent 一种颜色，按其负责的步骤与测试占比分段，通过一项描一段。
│  │  ├─ 未完成部分为同色虚点；正在工作的 Agent 在其描边末端显示闪烁圆点，不使用旋转弧。
│  │  └─ 颜色按 Agent 出现顺序取 --agent-0…5，同一 Agent 在树、概览、详情中颜色一致；用户验收节点不画。
│  ├─ 详情按类型展示：根任务（已确认要求、批准）、效果、测试（证据与自动修复）、验收。
│  ├─ 面向长任务：跨度大、约束少、几乎不可能一次做完（训练模型、写论文）；示例 examples/mcp-model-plan.json。
│  ├─ 拆得足够细：每步是 Agent 一次能做完并拿出证据的一件具体事；“改到达标为止”写成明确的几轮。
│  │  ├─ 示例：4 个阶段、18 个步骤、7 个测试，每个步骤带三类样例。
│  │  └─ 提交计划时，只有 1 个步骤的效果会被提示“可能拆得太粗”，让 Agent 再拆。
│  ├─ 所有节点（含根、效果、分组）的详情在右侧栏按四部分打开，布局自上而下：
│  │  ├─ 描述（居中）；输入（左）→ 输出（右）；测试（居中）。
│  │  ├─ 整个任务的详情：点左上角标题旁的图标，从顶部向下展开；含输入→输出、阶段路径、已确认的要求、Agent 分工、全部测试，以及批准、暂停、验收。
│  │  └─ 树上没有起点，也没有固定的“用户验收”末节点：顶层路径从第一阶段到最后一个阶段。
│  │  ├─ 描述：一两句话说明输入怎么变成输出，下面列出注意事项、先等谁、何时才做、没做到怎么办。
│  │  ├─ 测试（步骤与测试节点）：正常情况、边界情况、极端情况三组样例，每条“输入 → 应该得到”。
│  │  ├─ 测试（根、效果、分组）：其下的测试列表，附每个测试的样例通过数。
│  │  └─ 计划提交时，工具回复列出还没写全的部分，让 Agent 补全后再请用户批准。
│  ├─ 节点详情从画布上方或下方弹出，在远离节点的一侧，不遮住节点：
│  │  ├─ 悬停约 0.15 秒弹出预览，移开即收回；预览只供查看，光标可以穿过它继续悬停下面的节点。
│  │  └─ 单击节点打开全屏详情页，Esc 或 × 返回树；双击仍进入该节点。编辑在同一页面原位进行：描述、输入、输出、测试各自在原位置变成可编辑，其余设置收在“更多设置”。
│  ├─ 每个节点的验收在它的“测试”最后：节点执行完成后随时可看；不满意点“中止并回到这里”，可附一句意见。
│  │  └─ 随即暂停整个任务、撤销批准、停止正在进行的执行，该节点及依赖它的节点待重做，并打开该节点编辑；改完重新批准。整个任务仍在标题下拉的面板里验收。
│  ├─ Agent 进度描边：每个 Agent 一段干净的单线圆弧（颜色区分），只画已完成的部分；正在工作的那段轻轻呼吸。不再用手绘双线、虚点和闪烁圆点，节点轮廓也不再抖动重绘。
│  ├─ 缩放：缩小到 80% 以下时只显示节点名称，居中并随缩放放大，保持可读。
│  ├─ 右上角按钮一键展开或折叠所有子节点（含 Agent 工作），缩放比例不变，第一阶段停在原位；图标：向外扩为展开，向内收为折叠。
│  ├─ Agent 配置：只显示模型和思考力度；Agent 一律自动执行，不设方式。
│  │  ├─ 规划只用两种模型：简单用 claude-sonnet-5-5，难用 claude-opus-5-5；不符合时工具回复提醒 Agent 修改。
│  │  ├─ 统一入口：标题旁的 Agent 图标，查看每个 Agent 的分工、模型、思考力度、正在做什么和负责的步骤，点“调整模型与力度”修改；节点页面不显示也不修改模型与力度。
│  │  ├─ 负责规划统筹的主 Agent 一般用 claude-opus-5-5、思考力度高。
│  │  └─ 保存后生成新版本、需重新批准；宿主支持时 Agent 按这些设置启动子 Agent。
│  ├─ 界面不显示修饰性说明、眉题和重复信息：只保留标题、内容、状态与操作，以及停止执行前的后果提示和编辑冲突提示。
│  ├─ 界面不再提供“让 AI 修改”按钮：直接编辑节点，或在节点验收里“中止并回到这里”附上意见。
│  ├─ 样例结果：节点执行后，每个样例显示通过与否、实际发生了什么，以及人一眼能懂的证据。
│  │  ├─ 证据：命令行（命令与输出，过长保留末尾 8000 字）、截图、短演示录像、文字、链接。

│  ├─ 所有文字简短直白，非专业人士也能看懂；同一意思只写一次（服务说明与 skill 同样要求 Agent）。
│  ├─ 测试样例由 Agent 规划时自动生成（服务说明与 skill 要求三类各至少一个）；缺少时详情中可一键请 Agent 生成，改动形成新版本、需重新批准。
